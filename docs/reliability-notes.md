# Reliability Notes

> 记录 Agent Travel Planner 在工具调用可靠性方面的设计决策与踩坑。

## 已知失败模式

### 1. 高德 API 返回空结果

**症状**：POI 搜索无匹配
**降级策略**：重试 → 改写关键词 → 提示用户换关键词
**触发条件**：连续 2 次重试后仍空

### 2. LLM 编造未返回的景点地址

**症状**：LLM 输出的地址在 API 返回中找不到
**幻觉校验**：强制 prompt 约束 + Pydantic schema 拒绝额外字段
**测试方法**：用 50 条样本对比开启 / 关闭约束的幻觉率

### 3. LLM 工具调用超时

**症状**：amap MCP 进程 30s 未响应
**降级策略**：指数退避重试 2 次
**最终方案**：返回 "tool timeout" 错误给 LLM，由 LLM 决定下一步

## 设计权衡

- **不直接换 LLM**：与其替换更稳的 LLM，不如教当前 LLM 更守规矩（schema 约束）
- **不阻塞主流程**：单个工具失败不应让整个行程规划崩溃
- **日志优先**：所有降级与校验失败都要写日志，方便复盘
